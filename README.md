# Orrery

> 让 AI 助手像一位总指挥（Orchestrator）一样为你工作：听懂意图、拆解任务、派出专长各异的子代理、盯着进度直到真正完成。

Orrery 是 DeepSeek Harness 的一款 agent 预设（preset）。安装后，你会在预设选择器中看到 **Orrery**——选中它，助手立刻获得一整套为"认真做完一件事"而设计的工作方式。

## 为什么用 Orrery

普通 AI 助手容易"聊着聊着就偏了"：任务做到一半停下等你催、上下文一满就丢三落四、什么活都用同一个模型硬扛。Orrery 针对这些顽疾做了一整套设计：

- **听懂你的话**：一句"深度工作""仔细研究一下"，助手自动进入对应的工作模式；说"think"，它会用更深的推理档位回答你。开启语义分类后，即使不说关键词，助手也能听懂你的意图（分类失败自动按未命中处理，绝不误事）。
- **总指挥坐镇**：助手以"总指挥"身份统筹全局——简单的活直接干，复杂的活拆给专长子代理，能并行的绝不排队，每个子任务都有明确的交付标准和验收。
- **专业的事交给专业的模型**：九种任务类别（快速问答、深度分析、架构咨询……）与三个只读研究代理（代码检索 / 文档调研 / 架构建议）各自绑定最合适的模型链，主模型不可用时自动降级到备选，绝不悄悄乱换；**每条链都能在设置页里可视化配置**（指定模型与推理档位，未配则继承当前会话的路由），不需要的类别还能一键停用、不再出现在助手的目标清单里。只读研究代理还会用受白名单严格看管的命令行做检索——只读命令放行，写命令一律拒绝。
- **不催不停**：任务清单没做完，助手会自己接着干；你随时喊停它就停（你的打断永远优先）；供应商抖动时自动退避重试，连续失败会如实报告而不是假装没发生。
- **长任务不丢上下文**：上下文将满时，助手会被提醒在合适的时机自行整理记忆；逼近极限时自动压缩，绝不让重要信息被生硬截断。
- **后台任务不刷屏**：耗时的委派可以放后台跑，完成时只收到一条简短通知，想看细节再随时调取完整报告。关联任务还能**显式分组**：每个子任务的报告即时送达，同组任务全部落定后收到一条完成信号，子任务异常自动续推恢复，真阻塞可随时上报，你随时能恢复或终止它们。需要反复打磨的活可以选用续聊形态：子任务做完一轮后仍能追问和纠正，它记得之前的上下文，重启应用也不丢。
- **语义答案随手可得**：需要"跳到定义""谁在引用这个函数"时，在设置中开启 LSP 能力，然后在会话面板一键点亮（默认关闭，不打扰）——语言服务器的真实语义回答，不用时即刻消失；`lsp_rename` 还能做跨文件语义重命名（经版本护栏安全落盘，失败报告精确到文件）；设置里的管理面板可一键安装缺失的语言服务器（13 种语言社区目录）。
- **编辑更稳更省**：文件读取自带锚点，编辑逐锚校验、有一处对不上就整体拒绝——改得准、不毁文件、还省 token。锚点编辑是默认编辑方式（可配置回到传统编辑共存模式），每次编辑在会话中以逐行着色的 diff 面板呈现。被会话沙箱拦下的写入支持一次性升权重试（需审批）。
- **人不在屏幕前也不耽误**：助手需要你审批、回答问题、评审计划，或任务失败、跑完一件长活时，会以 DeepSeek Harness 自己的名义弹出一条系统通知（带它的图标）。你正看着窗口时默认不打扰（可改成始终通知）；同一会话的连续通知会合并并重新提醒，不同会话的通知互不覆盖。设置页「系统通知」组可调开关、最短时长、提示音与前台行为；该能力对当前 profile 下的所有会话生效，不限于 Orrery 预设。在 macOS 上，如果通知没弹出，可在同一组里点「通知权限」，面板会检测授权状态并一步步引导你在系统设置里允许 DeepSeek Harness。
- **发现不再白费**：子代理在工作中挖到的昂贵知识（哪个包管什么、验证过的硬约束、走不通的路）会写进本会话的"黑板"——同一事实不用挖第二遍，后来的子代理直接取用；两条代理同时想写同一条目时由写入权仲裁排队，胜者写完订阅者自动收到通知。右侧栏的黑板面板让你看到这些条目（按类型分组、可搜索），你也能亲手编辑——和助手一样先申请写入权；觉得某条值得长期保留，点面板里的「Evaluate for promotion」，助手会按使用量排序逐条给出晋升建议，由你裁决后才落进持久文档——在你点这个按钮之前，助手根本不知道"晋升"这回事。详见 [会话黑板](docs/features/blackboard.md)。
- **改动互不打架**：需要隔离的改动可以放进独立的 worktree 车道——每条车道有自己的分支和目录，派给它的子代理只能在该车道内读写，结束后宿主自动检查，合并前你会在卡片上确认改了什么、要不要合；合并后由你决定保留还是清理。信任度高的会话可以切到自动授权（两档：合并/放弃后保留或清理分支），跳过逐张卡片确认，新会话的默认档位在设置里调。还能开启会话级 Worktree 模式，让助手彻底不在主工作区动手；`/worktree` 命令和右侧栏的 Worktree 面板让你随时看清每条车道的状态。想等某条车道（包括别的会话开的车道）出结果时，助手可以订阅它的结论状态：到达目标或等待超时，都会恰好收到一条通知，不用反复询问。
- **多会话不再互相覆盖（实验）**：在设置里打开「编辑锁」并重启后，同一项目里的多个会话改文件前都要先持有该文件——别人正在改的文件你改不了，可以请求对方转交。停止会立即阻止新的编辑；已经开始提交的那一次写入仍可能完成，但不会让助手恢复编辑权。停止后你发的下一条消息即自动恢复编辑并确认保留的文件，无需再手动点「继续编辑」（设置里可关掉这个自动恢复）。助手每轮结束要释放用完的文件，确实还要用的只能有期限地保留；输入栏的「编辑锁」按钮只在需要你处理时给出一个动作。宿主停止父会话时也会取消正在运行的子代理；shell 和外部编辑器的改动不在保护范围内。
  一个既有文件的写入结果不明时，其他已确认无关的既有文件仍可继续工作；无法确认影响范围时仍会拒绝，不会自动重试或解锁。详见 [编辑锁的隔离边界](docs/features/edit-lock.md#管理器事务与发布)。
  设置页的「编辑锁维护」可在编辑锁关闭时查看已保存开关、实际运行状态与未决记录；修改开关仍须重启，关闭不会清除历史或解除未决阻塞。目录不存在或为空也不能证明从未有过历史。详见 [维护面板](docs/features/edit-lock.md#用户可见行为)。
  对无法查清结果的历史写入，管理员恢复 API 允许你在备份后明确接受迟到写入风险，一次释放旧会话全部占用，保留未知历史与审计；不自动重试，也不宣称文件已安全。当前交付为后端入口，维护面板按钮另行接入。详见 [管理员恢复](docs/features/edit-lock.md#管理员恢复admin-override)。

## 安装与启用

1. 在 Harness 会话中由 `plugin_manager` 以本仓库 `plugins/orrery-harness` 目录安装 bundle（link 安装，随源码更新）。
2. 打开 Web GUI 的预设选择器，选择 **Orrery** 创建新会话。想开发、调试或实验 DeepSeek Harness 本身时，改用 **Orrery 创造模式**：它是同一套 Orrery 工作方式，额外带上 DSH 创造模式的能力——只读运行时检查工具、持久化插件管理、四项 Cordis 插件/预设开发技能（首次会话即默认启用），并在系统提示词里内置了这套工具的使用指引。详见 [预设打包](docs/features/preset-packaging.md)。
3. 其他预设（如 standard）完全不受影响——Orrery 的一切只在它自己的会话里生效（唯一例外是系统通知，它挂在 profile 层、覆盖所有会话，可在设置页关闭）。

## 配置

打开全局设置的 **Orrery 设置页**，一站式调整：意图分类器档位（正则/LLM/Jev）、九种类别与三个只读研究代理的模型链（可视化编辑器，逐档位指定 provider / 模型 / 推理档位）、停用不需要的类别（逐类别勾选）、续推与退避上限、上下文压力阈值、锚点编辑开关、只读 shell 开关与白名单追加项（bash 三表 + Windows pwsh 两表；每张表都是**追加**到你产品默认项之上的额外条目，默认项始终生效、无法被移除）等。页面按卡片分区组织，细调参数收在各自总开关之下、翻动开关即时显隐（如 Jev 选项只在分类器选 Jev 时出现，pwsh 白名单只在 Windows 上出现），多级子项以缩进与引导线呈现；被隐藏选项的值原样保留。改动**在同一进程内即刻生效**，不需要重启应用：只读 shell 开关与白名单追加项、续推与退避上限、模型链与停用类别均作用于此后发出的委派，续推上限并即时作用于**已在监督中**的子代理。其余部分（如意图分类器档位）仍按应用启动时读入，改后需重启生效——这类选项行内常驻「需重启」标记，保存后还会弹出居中提醒，点名哪些改动要重启（可消除）。

## 内置工作技能

Orrery 自带十项开箱即用的工作技能，意图命中时自动加载，也可以随时手动调用：

| 技能 | 一句话说明 |
|---|---|
| `deep-work` | 证据驱动的端到端完成模式：不拿"看起来对了"当完成 |
| `research` | 深度研究：并行检索代码、文档与网络，产出带引用的综述 |
| `review-work` | 完工把关：先亲自在实际界面上验证，再从目标覆盖、代码质量、安全性审计 |
| `debugging` | 假设驱动的调试：先复现、排序假设、用最便宜的判别实验定位根因 |
| `git-master` | git 全科医生：原子提交、rebase、squash、blame、bisect、reflog、历史考古 |
| `refactor` | 重构向导：用正确的分解方式做重构、清理与重组 |
| `programming` | 语言实践纪律：Python/Rust/TypeScript/Go 的严格现代写法（含分语言参考） |
| `remove-ai-slops` | 清除 AI 代码异味：在回归测试保护下给分支改动"去腻" |
| `work-with-pr` | PR 全生命周期：独立 worktree 实现、证据绑定的手工验证、可读性优先的 PR 描述 |
| `remove-deadcode` | 死代码清理：安全验证 + 原子提交，删掉无人使用的代码 |

> 自「会话能力管理器」选择 provider 落地起：Orrery 会话只显示**已启用（已选）**的技能——未选中的第三方技能不再自动出现在目录、`skill` 加载与 `/` 菜单中；尚未产生选择记录的会话看到空目录与状态提示，选择由 Capabilities 面板显式编辑产生。详见 [会话能力管理器](docs/features/session-capability-manager.md)。
> MCP 同理：经 Orrery 配置的 MCP server 由 Orrery 统一挂载并可按会话启停（被拒调用不会到达 server）；宿主里直接配置的 server 显示为「未托管」，不会被自动接管。详见 [会话能力管理器](docs/features/session-capability-manager.md)「MCP 会话级关闭」。
> 团队能力集合（预设库）可保存/导入/导出并限定到本工作区，入口就在 Capabilities 面板的「预设」视图；导出按来源打包（远程技能记链接、本地与工作区技能随包带走），导入先给你看装进哪里、有无同名冲突，确认后才落盘且不会自动启用。还可以把选择保存为「工作区新会话默认值」——只影响之后的新会话。详见 [会话能力管理器](docs/features/session-capability-manager.md)「预设与默认值」。
> 已安装的第三方技能可以定期「检查更新」（只读、改动需你确认才发布；自动更新默认关闭），已接受的内容在来源更新后仍按会话原样可用，换用新内容需显式刷新。详见 [Skill 分发](docs/features/skill-distribution.md)。
> 会话输入栏的能力 Badge 直接显示本会话正在用哪些技能与 MCP server，点击打开右侧栏 **Capabilities 面板**（技能按来源分组勾选、MCP 管理、预设与默认值），无右侧栏时回退为原弹层；移除某项后模型会收到明确通知。详见 [会话能力管理器](docs/features/session-capability-manager.md)「管理界面与通知」。
> 打开历史会话时，技能菜单可能**先短暂为空**（冷会话不猜测、先空后收敛），页面完成一次自动恢复后即显示该会话的已选集合；若恢复失败（如另一进程占用会话），菜单保持为空并显示原因与处理提示。
