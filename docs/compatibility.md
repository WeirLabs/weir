# 版本兼容性（DSH 宿主支持矩阵）

> Weir 是运行在 DeepSeek Harness（DSH）宿主上的 agent 预设 bundle。DSH 目前迭代很快且常有破坏性变更，因此 Weir 对每个版本**声明且仅声明**经过验证的 DSH 兼容范围。本文档是该声明的唯一权威记录。

## 支持矩阵

| Weir 版本 | 支持的 DSH 版本 | 状态 | 备注 |
|---|---|---|---|
| **1.2.3** | `0.2.1-rc.2`（`>=0.2.1-rc.1 <0.3.0`，`engines.dsh` + `peerDependencies` 双声明） | **当前版本** | 新增意图门 `writing` 意图（写文档请求注入成品交付纪律）与意图表 `summary` 透传修复；三道门禁对 0.2.1-rc.2 树全绿（check / 单测 3037 / 集成 868），DSH 支持边界不变 |
| **1.2.2** | `0.2.1-rc.2`（`>=0.2.1-rc.1 <0.3.0`，`engines.dsh` + `peerDependencies` 双声明） | **自本版起需要 DSH ≥ 0.2.1 线** | 三道门禁对 0.2.1-rc.2 树全绿（check / 单测 2995 / 集成 868）；desktop 实况验收已过（版本闸门/预设挂载/设置页/委派垫片端到端/会话日志解码，并借此修掉 spawn 事实双前缀一处） |
| **1.2.1** | `0.2.0-rc.2`（`>=0.2.0-rc.2 <0.3.0`） | **DSH 0.2.0 线的最后支持版本** | 后续 Weir 版本将跟随更新的 DSH 运行时，可能抬升下限 |
| 1.2.0 及更早 | `0.2.0-rc.2`（同上） | 历史版本 | 早于本记录政策，未逐版本验证回溯 |

矩阵行的口径：`支持` = 该 Weir 版本在此 DSH 版本上通过全部三道门禁（静态检查、单元测试、集成测试），且 manifest 的版本闸门区间覆盖它。DSH ≥ 0.2.1 的兼容性检查优先按 `engines.dsh` 判定（存在时忽略 peer 条目），旧宿主回退到 `peerDependencies["@deepseek-ai/dsh"]`（AGENTS.md §3.8）。

## 政策

1. **一个版本一句话**：每个 Weir 版本在矩阵里恰好一行，声明它验证过的 DSH 范围。
2. **破坏性跟随**：DSH 发布破坏性版本（如 0.3.0）时，Weir 的新版本在适配后抬升 peer 下限，并在矩阵中标注「X.Y.Z 起需要 DSH ≥ …」；上一个支持旧 DSH 的 Weir 版本在矩阵中标注「DSH A.B 线的最后支持版本」。
3. **不承诺未验证的组合**：版本区间是闸门也是声明——区间外的新 DSH 可能能跑，但未经门禁验证，问题不追溯。
4. **验证方法**：升级 DSH 后重建运行时参考并核对版本一致性（AGENTS.md §2 的 dsh-src 重建与版本核对），然后跑全量门禁。

## 打版时更新本文档（强制）

打版流程（AGENTS.md §4.4）在固化 CHANGELOG 的同时必须更新本矩阵：

- 常规版本：在矩阵顶部加一行（或更新当前行）。
- 涉及 DSH 支持边界变更的版本：标注「最后支持版本」/「起需要」字样，并在 CHANGELOG 对应版本段开头加同样的提示。
