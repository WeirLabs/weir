# 编辑锁（edit-lock）

> **稳定、恒开、用户无感**：编辑锁随预设挂载，没有开关、没有命令、没有任何"需要你处理"的状态。它只做一件事——让**同一个文件在同一时刻只被一个会话写入**，撞上就明确拒绝，绝不静默覆盖。
>
> 输入栏保留一个状态指示（空闲 / 持有 N / 保护暂不可用）。面板里没有按钮；所有动作都属于模型。

## 概述

多个会话（同一窗口内的多个对话、或同一台机器上的多个 Harness 实例）编辑同一个项目时，两个写者可以各自通过版本校验、先后落盘，形成一次静默覆盖。编辑锁把"谁现在可以写这个文件"收敛到一个**回合级的短租约**上：

- 受管编辑器（受管 `write`、`hash_edit`、`lsp_rename`）在写入前取得目标路径的租约；
- 租约在**回合内**保持（多次工具调用复用），**回合结束自动释放**；
- 被其他会话持有时，本次编辑在落盘前被拒，文件字节不变；被拒的会话可以**订阅这个路径的下一次释放**（`edit_lock_watch`），拿到通知后再重新抢锁；
- 租约按路径滑动过期（120 秒无人触碰即可被他人取得），因此不存在"卡死"。

仲裁由一个独立的本机守护进程承担（`weir-editlockd`），它是**纯内存**的：任何时刻被 kill 都等价于"所有租约同时过期"，不需要任何恢复流程。

## 用户可见行为

- **输入栏指示**：Badge 只显示 `编辑锁`——空闲时就是这三个字，不加任何状态词；本会话持有文件时追加数量（`编辑锁 · 2`），保护不可用时追加 ` · 未加锁`。展开后是一块**只在有事时说事**的面板：什么都不占用时只有一行 `暂无文件占用。`；本会话持有时出现标题 `你正在编辑` 与其文件行（保留中的行尾带 `保留 N 分钟`）；其他会话持有时出现标题 `其他会话正在编辑` 与其文件行（行尾是持有者标签）；保护不可用时在最上方加一行琥珀色提示 `保护暂不可用，编辑不受影响。`。面板内**没有任何动作控件**，唯一的交互是展开/收起（再点 Badge、面板内 Escape、点击面板外均可收起）。
- **冲突只出现在模型那一侧**：另一个会话正在写某个文件时，模型拿到的是一条工具错误，里面点名持有者、剩余有效时间，并明确要求"不要盲目重试同一编辑，可以改用转交请求"。**这条错误不会弹通知、不会进 GUI、不会要求你做任何事。**
- **回合结束即释放**：不论回合是正常完成、你按了停止，还是模型出错，这一回合占用的文件全部释放，下一个会话立刻可以编辑。不再有"继续编辑""待确认""异常锁"。
- **跨回合保留**：模型可以在回合结束前显式保留文件（`edit_lock_hold`），最多 60 分钟；保留到期后自动释放：broker 照常广播这条过期事实（与显式释放同一出口），但**没有订阅者时对外完全安静**（不弹通知、不追问、不需要确认）；只有此前显式订阅了该路径释放的会话会收到一次「可以重新抢锁了」的提示。
- **等待下一次释放**：冲突或转交被拒之后，模型可以订阅一个路径的下一次释放（`edit_lock_watch`）。通知只是**重新抢锁的机会**：按路径点名、要求调用 `edit_lock_acquire`、并明确写着「不是所有权、也不预留」。多个会话可以同时等待同一次释放，都会被提醒，但 broker 不排队、不选主；先抢到的人赢，输的人收到普通的「他人持有」冲突，可以继续协商或再次订阅。运行中的会话在当回合收到通知，空闲会话被唤醒一次。
- **模型之间的转交**：需要别人手里的文件时，模型可以发一条转交请求（`edit_lock_try_steal`）。持有方会在自己的回合里收到（空闲时被唤醒一次，回合中则直接落进当前回合），可以答复释放（`edit_lock_reply`，`release`）或保留（`keep`）。不答复、超时或持有方已不存在，归属不变。结果（释放/保留/过期）会作为一条消息送达请求方，**即使发起请求的那个回合已经结束**——请求不随回合消失。
- **仲裁器挂了不影响编辑**：守护进程连不上、超时或起不来时，受管写入**照常进行**，并在审计里留一条 `weir/file-lease`（`kind: 'degraded'`，同一进程 60 秒内至多一条）。**真实冲突永远拒绝，绝不降级。**
- **同一任务内不互相挡**：派生子代理共享发起会话的归属，编排者与它派出去的子代理、以及同一会话的多个挂载之间永不因抢同一个文件互拒；互斥只发生在不同会话（不同 lineage）之间。

## 配置

**没有设置项。** 特性恒开，以下为固定产品值：

| 参数 | 值 | 含义 |
|---|---|---|
| 租约有效期 | 120 秒（按路径滑动） | 只由"碰这个文件"续期；到期即可被任意他人取得 |
| 单次保留上限 | 60 分钟 | `edit_lock_hold` 的上限，无累计额度 |
| 协商窗口 | 120 秒 | 转交请求的待答时限，过期即保留原归属 |
| 释放订阅超时 | 无 | 订阅只在命中、agent 销毁、连接重置或卸载时结束；没有独立的墙钟超时 |
| 守护进程空闲自退 | 60 秒（无客户端连接） | 有连接时永不退出 |
| 协议主版本 | 1 | 写进 socket 名；不同主版本各自独立 |

旧版本的 8 个 `editLock*` 设置键已退役。保存过它们的 profile **不需要清理**：旧值留在配置里不报错，也不再被读取。

## 设计细节

### 两态模型

租约只有 `held` 与 `requested` 两种状态，**会话层面不存在"编辑状态"**。这是与旧实现最本质的差别：状态机是复杂度的载体，删掉状态机比删掉代码更有效。

### 归属：lineage

`lineage` 沿会话头的 `parentSession` 上溯到 `delegationDepth === 0` 的根会话（最多 16 跳、带缓存；父会话解析不到时退化为直接父 id）。子代理、孙代理、同一会话的另一个预设挂载都属于同一 lineage，因此**永不与自己的发起者互斥**；不同 lineage 之间正常互斥。

编辑锁通过 `owner = { id: lineage, session, label }` 与仲裁器交互——`id` 是 lineage，`session` 是最后触达的会话（用于唤醒与释放），`label` 仅用于呈现。

### 仲裁守护进程（`src/lease-broker/`）

| 模块 | 行数 | 职责 |
|---|---|---|
| `protocol.js` | 237 | 帧校验、op 与事件名单、12 个错误码的闭集 |
| `state.js` | 482 | 纯内存租约表、协商 mailbox 与释放事实广播（无 IO、无真实时钟）；`settled` 自带 requester session |
| `server.js` | 402 | 本机 socket/命名管道、握手（含事件能力清单）、连接归属、空闲自退 |
| `entry.js` | 98 | 可执行入口（socket 路径、版本、信号） |

- **零持久化**：不写任何文件（socket 文件除外）。被 kill 等价于全部租约过期。
- **连接归属**：每个连接一个 id；连接关闭即释放该连接持有的全部租约。进程崩溃因此是"立即释放"，不必等 TTL。
- **释放事实**：显式释放、持有者连接断开、过期回收都在**删除租约之后**向所有在线连接广播 `released`（`reason` 为 `released` / `disconnected` / `expired`）；原子转交与空操作不广播。broker 不保存订阅、不排队、不选主。
- **整批全有或全无**：一次申请里任一冲突则一个都不授予。
- **幂等靠语义**：`acquire`/`release`/`hold` 重复执行结果相同；`reply` 绑 requestId，第二次必然落在 `expired`/`stale`。因此超时重试永远安全，不需要去重表。
- **地址**：POSIX `<tmpdir>/weir-editlockd-<uid>-v<protocol>.sock`；win32 `\\.\pipe\weir-editlockd-<sha256(homedir)[0..12]>-v<protocol>`。可用 `WEIR_EDITLOCKD_SOCKET` 覆盖（测试用）。
- **协议**：见 [编辑锁协议](edit-lock-protocol.md)（操作集、事件、错误码、幂等性论证、易失性契约）。

- **入参先做词法规范化**：`edit_lock_acquire` / `release` / `hold` / `try_steal` / `watch` 收到的每个路径都先经 `node:path` 的 `resolve` 折叠 `.`、`..`、重复与结尾分隔符（相对路径仍按会话 cwd 解析），批内去重发生在规范化之后。broker 只认字符串相等，所以 `/p/src/a.js` 与 `/p/src/../src/a.js` 在工具面是同一条路径：同一把锁、同一条订阅 entry、同一次在飞 `status` 读，别名既造不出第二把锁，也造不出第二个订阅。
- **进程级单例**：整个进程一个连接、一份清单，两个预设挂载共用；**不随挂载卸载关闭**（否则两个挂载会互相踩踏）。会话级清理由 `agent/disposed` 与连接关闭保证。释放订阅协调器按同一 client 共享（`WeakMap client → coordinator`），所以“一份清单”也包括“一张订阅表”。
- **内存清单只用于重放与释放，从不用于裁决**：裁决永远只在守护进程一处。`startedAt` 变化或连接重置时重放仍有效的保留；被他人抢走的条目直接剔除。
- **降级**：基础设施失败 → 一次重连重试 → 仍失败则无租约执行 + 审计（60 秒限流）。下一次调用必须重新尝试（不永久熔断）。
- **审计**：`AUDIT_TYPES.fileLease`（`weir/file-lease`），在降级发生的那一刻写入，含 `kind`、`owner`、路径数量与原因。

### 释放订阅（`edit_lock_watch`）

订阅分两半，各自只做自己那一件事：

**broker 只广播事实。** 任何让路径**不再有持有者**的动作——显式 `release`、持有者连接断开、观察/回收一条过期记录——都在**删除租约之后**向每条在线连接各发一次 `released`，带 `path` 与 `reason`（`released` / `disconnected` / `expired`）。原子转交（`reply(release)`）不广播，因为路径从未变成无主；重复释放、`acquire` 收养、`hold` 延长同样不发。broker 没有订阅表、没有等待队列、不选主、不预留归属。

**客户端自己做一次性订阅。** 整个进程只有一份**订阅协调器**，以共享 client 为键（`WeakMap client → coordinator`），因此两个预设挂载看到的是同一张 `(session, 规范化绝对路径)` 表。状态是闭集 `watching` / `hit` / `reset` / `self` / `cancelled`：

1. `edit_lock_watch` **先登记**、再通过共享 client 读 `status`（权威所有权只由 broker 回答）；同一 `(session, 路径)` 只有一条活跃 entry，重复调用（同一挂载或跨挂载）复用同一条 entry 与**同一次在飞的 `status` 读**，所以同一次释放不可能通知两次，并发调用也不会一个取消、另一个误报 `watching`；
2. 每次 `await` 之后——无论 `status` 成功还是失败——都先看终态：`hit` 返回 `released`、`reset` 返回重查结果、转交得到的 `self` 返回自有结果；这些终态**及其待投递通知**不会被后来的失败清理覆盖，清理只取消仍是 `watching` 的等待；
3. 只有 entry 仍以**同一对象**留在活跃表时，才按 `status` 回答 `watching` / `free` / `self`（`free`、`self` 终结并移除 entry）；已被替代的旧 entry 绝不会被并发调用误报为活跃；
4. 命中（`hit`）即从活跃表摘除并进入 `pendingDelivery`，通知在 `setTimeout(0)` 里延迟投递，**先消费后投递**，重复观察不会第二次通知；若命中时那条权威 `status` 读还在飞，通知会等它落地后才武装 timer，让该读的调用方先有机会用 `released`/`reset` 工具结果报告同一集——同一集只会有一个模型可见结果；`pendingDelivery` 保留到 timer 完成，因此 agent 销毁能同时取消活跃订阅与尚未投递的命中/重置通知；timer 触发时再检查终态、挂载引用与当前 live agent 身份，绝不把通知投给已销毁或被替换的 agent；
5. 路径已空闲或已归本会话时立即返回且不留下订阅；握手没有声明 `released` 能力、或 `status` 读不到时，显式报告不可用并清掉刚登记的条目。

通知走编辑锁既有的消息通道：完整 UserMessage、运行中 `steer`、空闲时 `followup` 唤醒一次。**一个 client 一份协调器、一条 entry、一次 status 读、一条通知**：两个挂载同时订阅同一 `(session, 路径)` 也只投递一次；单个挂载卸载只移除自己的引用，其他挂载仍共享的订阅与待投递通知转给存活引用，最后一个挂载卸载时才移除该 client 的 event/reset 监听并清空协调器。agent 被销毁后它的订阅随之消失，任何延迟中的通知都不会投递给已销毁的 agent。派生子代理拿不到这个工具，与其它所有权工具一致（子代理继续共享发起会话的归属，不需要也不能等待释放）。

`reset` 是终态：连接失效——socket 关闭、主动 drop/重试、显式 `close()`（包括拨号或握手尚未完成的窗口：关闭闩锁让共用这一次建立的所有调用方立刻以 `transport` 失败结算，底层 dial 永不返回也不会悬挂；之后才到达的 socket 只被关闭、不采用——不握手、不重放、不发请求、不回填清单；这一语义不引入任何拨号墙钟超时，被放弃的拨号留在后台收尾且其结果始终被消费），以及 broker 被 SIGKILL（它根本无法广播）——都会把活跃订阅标成 `reset`，给仍存活的会话投递「重新检查、必要时重新订阅」的提示，**绝不说路径已空闲**。同一连接恰好只发一次重置：失效入口只有一个，旧连接的迟到关闭是空操作。订阅不恢复、不重连重订、不持久化；agent 销毁、挂载卸载、以及一次成功的 `transferred` 结算都会取消对应等待，避免已经用另一条路拿到所有权的会话被自己的释放通知唤醒。

| 工具结果 | 含义 |
|---|---|
| `watching` | 另一会话仍持有该路径，已登记一次性订阅 |
| `free` | 当前无人持有；未留下订阅，模型应当直接抢锁 |
| `self` | 本会话已持有（含登记过程中转交成功）；未留下订阅 |
| `released` | 释放恰好发生在登记过程中；未留下订阅，也没有待投递通知 |
| `reset` | 登记过程中连接被重置；未留下订阅，要求重新检查 |
| `degraded` | `release-events-unsupported` / `watch-cancelled` / 传输失败；未留下订阅 |

### 协商结果的自路由

`settled` 事件自带 requester session 与路径，**这两项就是投递地址**：请求方在发起请求的那个回合里得到 pending 回执，结果（`transferred` / `declined` / `expired`）不依赖那个回合是否还在。回合结束会清掉挂载内的 requestId 路由（那是路由备忘，不是所有权事实），而协商本身按 broker 的窗口活着——所以 `declined` / `expired` 仍会按 `(session, 路径)` 作为一条消息送达请求方；没有这条地址的旧 broker 才回退到 requestId 路由，两者都没有的事件属于别的进程，直接忽略。

一次成功的 `transferred` 会在投递之前先按 `(session, 路径)` 终结对应等待（含已命中但尚未投递的释放通知）：路径已经归本会话，再被自己的释放通知唤醒没有意义。投递本身是**进程级至多一次**：同一进程中多个预设挂载会听到同一条事件，投递记账按 agent 保存已送达的 requestId（有界 FIFO），与 `issued` 路由无关，所以既不会因为回合结束而丢，也不会因为多挂载而重。记账以 broker 化身分界：新化身从自己的零重新分配 requestId，重置信号随即使旧记账失效，因此新请求的同号事件仍会正常送达。

### 接线

三个受管编辑器直接 import 同一客户端模块（不经 cordis 服务）：

| 编辑器 | 行为 |
|---|---|
| 受管 `write`（`src/hashline-edit/write-tool.js`） | 保留"覆盖前必须读过"的观测守卫与 diff 输出，用 `withLeases` 包住写入 |
| `hash_edit` | 锚点校验、版本 CAS、沙箱策略不变，只把发布包进 `withLeases` |
| `lsp_rename` | 整批 `withLeases`；Phase 1 预检零写入不变；失败按 `filesAlreadyWritten` / `filesNotWritten` / `filesUncertain` 三清单报告并声明不回滚 |

预设的两行（`weir` / `weir-creative`）以 `weir-harness/file-lease` 挂载，**没有 cordis 服务、没有 `isolate`、没有行序约束**。

### 只读状态面

唯一端点是 `POST /api/weir-edit-lock/view`（宿主认证通道），返回 `{ schemaVersion: 1, arbiter, mine, others }`。路径按会话 cwd 呈现短名；输出**不含** epoch、generation、保留期预算、恢复计数等内部字段。端点只读：不改租约、不写对话、不写审计。

## 边界与失败语义

- **冲突零副作用**：被拒的编辑不写字节、不创建文件、不派发沙箱写入。
- **进程崩溃**：连接关闭 → 守护进程立即释放该连接全部租约。
- **守护进程崩溃/被 kill**：全部租约消失；下一次受管编辑重新申请；客户端重连后重放自己的保留（抢不回来的剔除）。
- **守护进程卡死/拉不起来**：连接超时 → 一次重试 → 降级放行 + 一条审计。整条路径不会挂死。
- **协议主版本不匹配**：socket 名含主版本，不同主版本各自独立、互不仲裁；错配的连接被服务端以 `protocol-mismatch` 拒绝并关闭。
- **跨进程**：仲裁器是中立枢纽，两个 Harness 实例共享同一 socket 与同一张表；互斥与协商都跨进程有效。
- **可重入**：同一 lineage 的重复申请是 adopt + 刷新，不构成冲突。
- **释放订阅不改变所有权**：通知丢失、晚到或被忽略都不影响任何裁决；下一次 `edit_lock_acquire` 仍以 broker 为唯一事实源，可能成功、也可能正常冲突。
- **旧 broker 不支持释放事件**：握手没有 `events` 时 `edit_lock_watch` 返回显式 `release-events-unsupported` 且不留订阅；其余编辑锁行为完全不变，旧 daemon 空闲退出后新 daemon 自动获得该能力。握手新增的 `events` 清单是协议主版本 `1` 内的向后兼容扩展（见 [协议文档](edit-lock-protocol.md)）。
- **重启不恢复订阅**：订阅只存进程内存；进程或 broker 重启后没有任何订阅被重建，也没有补发通知。

### 已知限制

1. **没有"未决发布"取证**：不再有 `prepared`/`publishing`/`unknown` 的持久账本，也没有围栏。写入是否落盘只由工具结果表达；`lsp_rename` 中途失败仍诚实列出三清单，但**不再保留围栏阻止后续写入**。这是刻意的能力放弃。
2. **shell 与外部编辑器不在保护范围**：它们不经过受管编辑器，编辑锁看不到。
3. **本机 socket 不做认证**：同用户的其他进程可以申请租约。与既有的本机通道同级；只读 view 端点走宿主认证，不受影响。
4. **网络文件系统不支持**：仲裁依赖本机进程，不承诺跨机器或网络盘语义。
5. **跨进程协商的一条边界**：持有方所在进程已退出时，请求会因找不到 agent 而被丢弃（该连接的租约同时已释放，因此不构成阻塞）。
6. **GUI 级自动化验收缺失**：旧的"双 GUI"验收工作流随旧面板一起删除；新 Badge 的行为由 chunk 测试覆盖，未在 CI 里跑真实浏览器。
7. **释放通知不保证路径仍然空闲**：通知只是事实广播的提示，其他等待者可能先抢到；broker 不预留、不排队。
8. **测试覆盖的边界**：以下语义**没有**自动化集成场景，但已在真实运行或人工实验里验证——空闲持有者的 `followup` 唤醒（单回合 headless 启动在首个 `turn/end` 即退出，不存在「存活且空闲」的会话，因此**结构上无法在集成里覆盖**，只有单测）、请求方 `settled` 通知的投递、超过 60 秒后的第二条降级审计、TTL 到期的持有者释放（现有场景走的是更强的「连接关闭即释放」）。回合结束释放、回合中唤醒投递、lineage 共享、释放通知的竞态与连接重置已由 `filelease-*` 场景覆盖。

与编辑锁相关的集成场景：

| 场景 | 锁定的行为 |
|---|---|
| `editlock` | 工具面（stock `edit`/`write` 隐藏、受管 `write` 与 `hash_edit` 在列）、受管发布、`status`、`hold`、`release` |
| `editlock-hashline-negatives` | 锚点命中/未命中、`>>> mismatch`、版本 CAS、diff 输出、沙箱拒绝标记、目标字节不变 |
| `editlock-lsp-rename` | 整批预检、冲突零写入、三清单、不回滚 |
| `editlock-lsp-uncertain` | 第二批未知错误 → `filesUncertain`、已写文件不回滚 |
| `filelease-turn-release` | 第二个 owner 被拒（`held` 且点名持有者）；`turn/end` 后仲裁表为空；目标字节等于受管写入内容 |
| `filelease-hold` | 保留报出到期时间；回合结束后**仍持有**（与上一条构成正反对照） |
| `filelease-degrade` | 仲裁器不可达时写入照常；两次写入都降级；工具报告"不可达"而非冲突；审计恰好一条 |
| `filelease-fault-injection` | 真实守护进程被 SIGKILL 后：旧化身不再应答、后续写入不被阻塞、整轮 < 90 秒 |
| `filelease-negotiation` | 冲突 → 请求 pending → 持有方 `release` → 请求方取得、原持有方再写被拒；另一条路径 `keep` → `declined` |
| `filelease-lineage` | 父会话持租约时，深度 1 的子代理可写同一文件（同 lineage 不互斥）；父回合当时仍在运行；外来 lineage 被 `held` 拒绝并点名持有者 |
| `filelease-wake` | 回合中收到转交请求：通知按序先于 `turn/end`、持有者当回合获得 `edit_lock_reply` 并 `transferred`、**不额外唤醒**、请求方随后取得 |
| `filelease-holder-death` | 持有进程被 SIGKILL 后 1 秒内租约可被取得（实测 2ms），且无死进程残留行——走连接关闭释放，不等 TTL |
| `filelease-release-watch` | 真实 broker 上两个等待会话：转交被拒 → 订阅 → 一次释放广播到每条连接 → 第二个等待者先抢到 → 订阅方收到一次通知、普通 `held` 冲突并成功再次订阅 |
| `filelease-watch-reset` | 活跃订阅期间 SIGKILL broker：旧订阅显式终止、收到「重新检查」而非释放通知、重启后新化身上的释放广播不再触发任何旧通知 |

### 回归基线（重写前后逐字不变的编辑行为）

重写完成后仍原样通过的安装版场景：`editlock`、`editlock-hashline-negatives`、`editlock-lsp-rename`、`editlock-lsp-uncertain`——它们的断言已去掉「权威镜像 / 未决发布 / 保留锁」这些随机制删除的部分，保留锚点、版本 CAS、diff、沙箱拒绝、三清单与不回滚。

重写**新增**的行为由 `filelease-*` 场景验收，不构成"回归"：回合释放、保留跨回合、降级放行、仲裁器被杀、协商转交、lineage 共享、回合中唤醒、持有进程死亡、释放订阅竞态与连接重置。

`editlock-lsp-uncertain` 中被**刻意放弃**的两条断言是：`unknown` 发布的 resource fence，以及"失败批次保留双锁"。删掉它们等于承认这次能力放弃，不是回归失败。
