# 拉取式后台通知（background-notification）

> 后台任务完成只来一条短通知，想看细节再拉全文——上下文不被报告原文淹没。

## 概述

后台工作（bash 后台任务、后台委派的子代理）结算时，agent 收到的是紧凑通知：job 标识、类型、终态、一行摘要。完整输出留在 job 里，由 agent 自主决定何时用 `job_output` 拉取——"拉"的决定权在 agent，不在通知。本特性直接采用 DSH 内建 job 道，Orrery 只做配置与纪律约束，不另建插件。

## 用户可见行为

- 后台任务完成 → 一条英文模板的紧凑通知（含标识与状态；标签/摘要等实例内容跟随会话语言）。
- agent 忙时通知注入下一步（不唤醒、不插话）；空闲时作为后续消息唤醒。
- 已被 `job_output`（wait 收集）领取的结算不再重复通知。
- 通知永远不含报告全文；全文经 `job_output`（流式游标）或按绝对偏移拉取。
- 唤醒风暴防护：连续自动唤醒上限 8 次。
- **分组合并**：受监督委派分组（见 [category-delegation](category-delegation.md)）的成员结算不走逐条通知——组全员终态后**恰好一条**合并组报告在回合边界送达。未分组结算维持内建逐条通知。

## 配置

| 键 | 默认值 | 说明 |
|---|---|---|
| `maxConsecutiveWakes` | `8` | 预设对 tool-jobs 的配置：连续唤醒上限 |

其余行为由 DSH 内建 job 道提供。

## 设计细节

- 采用内建道的依据（源码级验证）：内建通知文本紧凑受字节上限约束、时机已是"排队注入"（busy→inject / idle→followup）、`awaited` 标记抑制已收集通知、模型主动 kill 的不通知。
- 一次性后台子代理与普通后台 job 共用同一条 job 道（kind `subagent`），语义统一。
- 拉取纪律写入 Orchestrator doctrine（先拉再断、不在通知里塞全文）。
- 已知留白：同一窗口内多个**未分组**结算不合并（每条结算一条通知，内建行为）。合并语义按设计收缩到组作用域：受监督分组在组完成时合并为一条报告（已由分组合并特性落地）。

## 边界与失败语义

- 已收集（awaited）、teardown、模型 kill 的结算**保证**不产生通知。
- 通知超出字节预算时优雅截断，不丢终态信息。

## 测试

- 集成测试：`delegate` 场景的后台道断言（紧凑通知、job_output 拉取）覆盖主路径；`grouped` 场景断言分组合并报告恰好一条且含全部成员。
